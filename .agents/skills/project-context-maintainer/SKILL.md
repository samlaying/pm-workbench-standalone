# 项目上下文维护 Skill

## 目标

把任何项目相关输入沉淀成可复用的项目记忆，让后续写 PRD、整理会议纪要、拆任务时不用重新解释背景。

## 公共规则

先读 `../_shared/workflow-rules.md`，并按其中的「结构化确认」「项目识别」「上下文获取」执行。本 skill 是项目记忆更新规则的事实来源；其他工作流 skill 只引用，不重复定义。

## 项目文件结构

```
项目目录/
├── 项目上下文.md
├── 内部术语表.md
├── 项目工作记录.md
├── 任务.md
├── 会议纪要/
└── 需求点/
    └── {{需求点名称}}/
        ├── 01-理解.md
        ├── 10-过程记录.md
        ├── 100-成品.md
        └── 500-复盘.md
```

无文件时按 `templates/` 创建。

## 每次处理流程

1. 按公共规则确认项目和需求点归属。
2. 按公共规则读取最小上下文。
3. 判断当前输入属于独立项目，还是大项目下的小需求点。
4. 用“新来的实习生不问人能否看懂”检查术语；公司内特殊含义必须进入 `内部术语表.md`。
5. 从输入提取可沉淀信息：
   - 背景变化
   - 项目目标/范围
   - 关键决策
   - 需求点新增/变更
   - 相关人和分工
   - 风险、约束、待确认问题
6. 只对会影响后续工作的缺口做结构化确认，每次 1-3 个问题。
7. 更新对应文件，并在 `项目工作记录.md` 追加本次来源和摘要。

## 框架性学习支持

当用户面对一个不熟悉的领域或复杂任务时，本 skill 可以充当"快速建认知地图"的角色：

- **已有资料扫描**：快速读取项目上下文、历史会议纪要、需求点文件，帮用户识别"已经知道什么"和"认知盲区在哪"。
- **术语扫盲**：内部术语表中的条目就是用户已有的认知资产；缺失的术语就是需要学习的盲区。
- **找人建议**：从会议纪要和项目上下文中提取"谁参与过相关讨论"，帮用户识别"可以找谁聊"。

这个能力主要在 `task-arrangement-planner` 的"框架性学习"步骤中被调用，不需要用户显式触发。

## 项目层级判断

- **独立项目**：当前输入围绕一个完整产品/能力。
- **大项目下的小需求点**：输入有整体项目背景，但用户只负责其中一个模块、流程、页面或事项。

不确定时必须问：`这是独立项目，还是大项目下的一个小需求点？`

## 需求点文件规则

创建需求点时，预制标准文件：

- `01-理解.md`
- `10-过程记录.md`
- `100-成品.md`
- `500-复盘.md`

行动项写入需求点 `10-过程记录.md`；项目级 `任务.md` 只做汇总视图。

## 输出格式

完成后给用户：

- 本次更新了哪些项目记忆
- 哪些信息仍待确认
- 后续写 PRD/会议纪要/任务安排时应复用哪些背景

不要输出完整文件全文，除非用户要求。
