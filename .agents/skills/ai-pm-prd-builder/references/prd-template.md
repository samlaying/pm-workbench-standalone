## 一、背景

### 1.1 业务场景

描述当前的业务现状、痛点、机会。来源于阶段零和阶段一与用户的交互结果。

**填写规范：**
- 说清楚是谁、在什么场景下、遇到什么问题
- 附上具体数据（如有的话）：影响了多少人、造成了多少损失、当前效率是多少
- 不要写抽象的套话

### 1.2 为什么用大模型解决

说明选择大模型方案的合理性。

**填写规范：**
- 回答三个问题：传统方案为什么不行？大模型能带来什么？有没有做过可行性验证或竞品调研？
- 如果竞品已在用 AI，附上效果对比

### 1.3 品质分析

对现有方案或竞品的品质进行分析。

### 1.4 产品目标

明确双层目标：

- **业务目标：** 可量化的业务指标（如：问题解决率提升至 X%、效率提升 X%、成本降低 X%）
- **模型目标：** 可量化的模型指标（如：回复准确率 ≥ X%、对话质量评分 ≥ X）

## 八、评测体系

### 8.1 评测集构建

**数据来源：** （说明评测数据从哪里来）

**规模标准：**

| 阶段 | 最低评测条数 | 说明 |
|---|---|---|
| 初期/MVP阶段 | 覆盖核心场景即可 | 快速验证可行性 |
| 中级阶段 | 200–500条以上 | 四类场景均需覆盖 |
| 成熟阶段 | 500条以上 | 持续扩充，每月回顾 |

### 8.2 评测维度与评分标准

| 维度 | 分值 | 1分（差） | 3分（及格） | 5分（优秀） |
|---|---|---|---|---|
| 准确性 | 0–5 | 事实错误、答非所问 | 基本正确，有小瑕疵 | 完全准确、信息可靠 |
| 完整性 | 0–5 | 严重遗漏关键信息 | 覆盖主要信息 | 全面覆盖、详尽完整 |
| 格式规范 | 0–5 | 格式混乱、不可用 | 基本符合格式要求 | 格式标准、开箱即用 |
| 安全合规 | 0–5 | 出现违规/敏感内容 | 无违规内容 | 主动规避风险 |
| 表达质量 | 0–5 | 语句不通、难以理解 | 表达清晰流畅 | 语言优美、超预期 |

**评分机制（可根据场景自定义权重）：**

> 总分 = 准确性×30% + 完整性×25% + 格式规范×15% + 表达质量×30%
>
> **安全合规为一票否决项：** 该维度 ≤ 2分，无论总分多少，判定为不达标。

### 8.3 评测执行流程

**评测方式：**

| 方式 | 适用场景 | 成本 | 可靠性 |
|---|---|---|---|
| PM自评 | MVP阶段快速验证 | 低 | 中（存在主观偏差） |
| 标注团队评测 | 灰度/全量阶段 | 中 | 高 |
| LLM-as-Judge自动评测 | 日常回归、高频迭代 | 低 | 高（需校准） |
| 人机混合盲测 | 生图、生文等生成类场景 | 高 | 很高 |

**评测触发条件：**
- Prompt 任何变更 → 必须跑核心子集（≥50条）
- 模型版本升级 → 必须跑全量评测集
- 线上 Bad Case 累计 ≥ X 条 → 触发专项评测
- 周期性回归 → 每月至少一次全量评测

**达标标准：** 评测达标后方可进入灰度/全量发布流程。

### 8.4 持续维护机制

- 评测集定期扩充计划
- 评分标准的更新机制

## 九、效果保障和稳定性策略

定义从模型输出到用户看到结果之间的所有质量控制手段。

### 9.1 模型输出层保障

| 保障手段 | 说明 |
|---|---|
| 输出过滤 | 敏感内容检测与拦截 |
| 格式校验 | 验证输出是否符合预定义 Schema |
| 质量兜底 | 低置信度结果的降级处理策略 |

### 9.2 中间处理层保障

| 保障手段 | 说明 |
|---|---|
| 结果后处理 | 模型输出的二次加工与规范化 |
| 规则兜底 | 关键场景的硬规则覆盖 |
| 缓存策略 | 高频问题的缓存复用机制 |

### 9.3 用户呈现层保障

| 保障手段 | 说明 |
|---|---|
| 降级方案（Fallback） | 模型不可用时的替代方案 |
| 超时处理 | 超时场景下的用户提示与回退 |
| 加载状态设计 | 长等待时的用户体验优化 |

### 9.4 监控与告警

| 监控维度 | 说明 |
|---|---|
| 线上指标监控 | 准确率、延迟、调用量等核心指标 |
| 异常自动告警 | 指标异常时的自动通知机制 |
| Bad Case 自动采集 | 线上失败案例的自动收集与分析 |

来源：阶段三中各节点的异常处理定义，汇总到此处。
