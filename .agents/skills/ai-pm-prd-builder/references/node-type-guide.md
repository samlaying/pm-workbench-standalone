# 节点类型选择与模型选型指南

此文件为 SKILL.md 的阶段二和阶段四提供详细参考。当 Skill 在与用户讨论节点类型划分或模型选型时，按需加载此文件。

---

## 一、节点类型详解

### 1.1 代码节点（Workflow 节点）

**适用场景：**

| 特征 | 说明 | 举例 |
|---|---|---|
| 每次结果必须一样 | 确定性逻辑，不允许随机性 | 读取数据库、调用固定 API |
| 出错有业务风险 | 误操作后果严重 | 发送邮件、修改订单状态、转账 |
| 规则明确 | 逻辑可以用 if-else 完整描述 | 权限校验、金额校验、字段格式检查 |

**产品设计要点：**
- 代码节点不需要 Prompt
- 但需要定义清晰的输入输出格式和错误处理逻辑
- 关注点：接口定义、超时处理、重试策略、降级方案

### 1.2 Agent 节点

**适用场景：**

| 特征 | 说明 | 举例 |
|---|---|---|
| 需要理解、综合、判断 | 综合多个信息源做推理 | 客户阶段判断、风险评估、需求分析 |
| 需要多步推理 | 不是一次调用能完成的 | 生成跟进方案（先分析再生成再验证） |
| 需要调用多个工具 | 模型需要自主决定调用什么工具 | 搜索信息 + 整理 + 输出报告 |

**产品设计要点：**
- Agent 节点需要完整的节点契约（输入/输出/行为边界/异常处理）
- 需要设计 System Prompt
- 需要考虑 Agent 的循环上限（防止无限循环）
- 需要定义工具调用的权限范围

### 1.3 LLM 单次调用节点

**适用场景：**

| 特征 | 说明 | 举例 |
|---|---|---|
| 简单的分类 | 输入→分类标签 | 意图分类、情感判断 |
| 简单的提取 | 从文本中提取结构化信息 | 从邮件中提取日期、金额 |
| 简单的格式转换 | 将一种格式转为另一种 | 自然语言→SQL、文本→JSON |
| 简单的生成 | 一次性生成短文本 | 生成摘要、生成标题 |

**产品设计要点：**
- 相比 Agent，结构更简单，不需要循环和工具调用
- 但仍需要定义 Prompt、输出格式、异常处理
- 适合用更轻量的模型（成本低、速度快）

### 1.4 节点类型选择速查表

| 场景特征 | 选什么 | 为什么 |
|---|---|---|
| 每次结果必须一样 | 代码节点 | AI 有随机性，固定流程不能交给它 |
| 出错了有业务风险 | 代码节点 | 比如发错邮件、改错数据，必须由代码控制 |
| 需要理解、综合、判断 | Agent 节点 | 需要模型推理 |
| 需要多步推理才能完成 | Agent 节点 | 需要先分析再生成再验证 |
| 简单的分类或提取 | LLM 单次调用 | 不需要 Agent 的循环能力 |
| 不确定 | 先用 LLM 单次调用验证效果 | 效果不够再升级为 Agent |

## 二、模型选型指南

### 2.1 核心原则

> **效果够用的前提下，选最轻量的模型。**
> 先用小参数模型验证，效果不行再升级。

### 2.2 选型约束条件

| 约束维度 | 问题 | 影响 |
|---|---|---|
| 推理成本预算 | 单次调用不超过多少元？ | 决定能否使用大参数模型 |
| 延迟要求 | 用户能接受多长等待时间？ | 大模型通常更慢 |
| 部署方式 | 用云端 API 还是私有化部署？ | 私有化需要考虑算力 |
| 数据合规 | 数据能不能出域？ | 限制了可用的模型范围 |
| 许可协议 | 能否商用？ | 开源模型需检查 License |
| 微调需求 | 是否需要在特定领域微调？ | 增加成本和复杂度 |

### 2.3 常见模型能力分层

| 层级 | 典型参数量 | 适用场景 | 特点 |
|---|---|---|---|
| 轻量级 | 1B–7B | 简单分类、提取、格式转换 | 成本低、速度快、能力有限 |
| 中量级 | 7B–30B | 多数生产场景 | 性价比最优区间 |
| 重量级 | 30B+ / 闭源旗舰 | 复杂推理、多步任务、高要求生成 | 能力最强但成本高、延迟大 |
| 多模态 | 各级均有 | 需要理解图片/音频/视频的场景 | 选择取决于模态需求 |

### 2.4 选型决策流程

```
明确约束条件（成本、延迟、合规）
   │
   ▼
列出候选模型（基于约束筛选）
   │
   ▼
用评测集跑效果对比
   │
   ▼
效果相近？ ──是──→ 选更轻量的
   │
   否
   ▼
效果差距大？ ──是──→ 选效果更好的（评估成本是否可接受）
   │
   否
   ▼
考虑微调轻量模型是否能追平
```

### 2.5 多节点选型注意事项

当产品有多个节点都需要大模型时：

- **逐个节点评估**，不同节点可能适合不同模型
- **用一张表汇总**，标注每个节点的选型及理由
- **考虑一致性**：如果多个节点之间有上下文传递，尽量选择同系列模型以减少格式差异
- **预留 failover**：每个主模型配一个备用模型
