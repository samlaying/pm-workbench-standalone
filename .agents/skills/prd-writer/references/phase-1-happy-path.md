# Phase 1：Happy Path

## 目标

先把正常路径讲清楚。

## 动作

1. 简要概括核心需求。
2. 按用户操作顺序整理页面/组件。
3. 每个页面写功能定位、触发条件、核心流程、信息架构、字段、交互、文案、权限/角色。
4. 对评审走查材料，每个页面必须补充“用户看到什么、用户能做什么、然后发生什么、评审待确认”。
5. 涉及跳转必须写清楚目的地。
6. 对产品机制补充可开发规则：目标结果、用户状态、系统状态、触发条件、完成定义、异常兜底。
7. 对每个关键操作补充难缠用户校验：1 秒内状态反馈、成功可感知、失败可补救、输入内容保留、空态/到底提示、高风险操作确认。
8. 不确定处标记 `【待确认：...】`。

## 输出

优先使用 `templates/happy-path-template.md`。

每个页面/组件至少包含：

- 功能定位
- 触发条件
- 用户看到什么
- 用户能做什么
- 然后发生什么
- 字段和文案
- 跳转目标
- 评审待确认

暂停点：每个页面/组件必须通过结构化确认来确认一次，确认后进入异常场景；未确认页面只能保留为候选稿。

质量参考：`v0-to-v1.md`。
