# 项目与 PRD 落位规则

项目根目录以存在 `项目上下文.md` 为识别标志；目录名称和编号不作强制要求：

```text
项目目录/
├── 项目上下文.md
├── 内部术语表.md
├── 项目工作记录.md
├── 会议纪要/
├── 需求点/
│   └── 需求点名称/
│       ├── 01-理解.md
│       ├── 10-过程记录.md
│       ├── 100-成品.md
│       └── 500-复盘.md
└── 100-成品.md
```

## 判断顺序

1. 优先根据输入文件位置确定项目；不要根据内容自行猜项目。
2. 无法从文件位置判断时，才通过结构化确认询问用户属于哪个现有项目。
3. 判断当前任务是独立项目，还是大项目下的小需求点。
4. 创建或更新需求点时，优先使用既有目录；没有目录再创建。

## 落位规则

- 独立项目：PRD 写入项目根目录的 `100-成品.md`，过程写入 `项目工作记录.md`。
- 大项目下的小需求点：PRD 写入 `需求点/{{需求点名称}}/100-成品.md`，过程和待办写入 `需求点/{{需求点名称}}/10-过程记录.md`。
- 若已有不同命名的当前 PRD，沿用现有文件名，不为了统一而改名。
- 过程信息不写进最终 PRD 正文。

## 项目记忆

项目记忆由 `project-context-maintainer` 负责。PRD 写作前必须读取并维护：

- `项目上下文.md`
- `内部术语表.md`
- `项目工作记录.md`

术语判断标准：新来的实习生只看项目资料、不问任何人，能否理解该词在本公司、本项目里的含义和边界。
