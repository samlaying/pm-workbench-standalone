# Phase 2：异常场景

## 原则

每个异常都回答三个问题：

1. 什么情况下发生？
2. 用户看到什么？
3. 系统怎么处理？

不要写“网络异常 -> 提示错误”这种只有分类没有场景的描述。

## 穷举角度

| 角度 | 思考方式 |
|------|----------|
| 操作中断 | 用户中途离开、切应用、锁屏、重复进入后怎么衔接 |
| 状态变化 | 业务状态被他人、其他入口或时间改变后怎么处理 |
| 时间推移 | 数据过期、会话超时、长期未操作怎么处理 |
| 外部结果 | 外部服务成功但数据不全、部分成功、超时、失败时怎么处理 |
| 多端/多入口 | 用户在不同设备、不同入口操作同一份数据时怎么一致 |

## 输出

| 步骤 | 异常场景 | 触发条件 | 用户看到什么 | 系统怎么处理 | 是否写入 |
|------|----------|----------|--------------|--------------|----------|

暂停点：必须通过结构化确认逐条或分批确认异常处理方式。确认后的异常写入 PRD，未确认的保留待确认标记，不要瞎写成既定方案。
