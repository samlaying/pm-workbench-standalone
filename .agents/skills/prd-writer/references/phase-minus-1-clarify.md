# Phase -1：任务澄清

## 触发

用户只给一句模糊指令，缺项目、材料、交付物、受众或深度。

## 做法

1. 先判断已知信息和缺口。
2. 每次只问会影响方向的关键问题。
3. 确认交付物、受众、需求范围、项目层级、期望深度。
4. **外部视角追问**：当需求涉及多模块、多角色、或方案不确定时，额外问一个升级问题——"如果目标是这个，当前方案是最好的吗？"。这一步不是为了推翻方案，而是确保 PRD 从一开始就站在正确的目标上。简单需求跳过此步。
5. 将澄清结论写入 `项目工作记录.md`；关键背景同步到 `项目上下文.md`。

## 输出

| 维度 | 当前判断 | 待确认 |
|------|----------|--------|
| 项目/需求点 | | |
| 交付物 | PRD 初稿/评审稿/飞书文档 | |
| 受众 | MT/研发/测试/跨部门 | |
| 深度 | 轻量/标准/完整 | |
| 外部视角 | 当前方案是否最优（仅复杂需求） | |

暂停点：必须通过结构化确认来确认任务范围和下一阶段；未确认前不要继续生成 PRD 正文。
