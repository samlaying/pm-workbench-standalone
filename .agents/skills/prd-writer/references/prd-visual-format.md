# PRD 视觉标记规范

> 需求文档不是一堆文字，是一张清晰的图纸。通过统一的标记体系，让读者一眼抓住重点。

## 一、标注规范（PM-研发沟通）

> **仅在 Phase 7 飞书上传时应用。** Phase 3 本地 Markdown 输出不使用此规范，保持文档简洁。上传飞书时，按此规范为关键信息添加标注，方便评审人快速扫描待确认项、优先级和依赖关系。

### 1.1 优先级标记

| 标记 | 含义 | 飞书视觉样式 | 使用场景 |
|------|------|-------------|---------|
| `[P0]` | 必须做，不做不能上线 | 🔴 红色文字 + 加粗 `rgb(232,63,63)` | 验收标准、功能点 |
| `[P1]` | 重要，影响体验但有 workaround | 🟠 橙色文字 `rgb(222,120,2)` | 验收标准、功能点 |
| `[P2]` | 锦上添花，可后排 | 🔵 蓝色文字 `rgb(51,112,255)` | 验收标准、功能点 |

**用法：** 标记放行首，正文跟在后面，不打断阅读。
```
[P0] 欢迎弹窗不可跳过，无跳过按钮
[P1] 搜索框始终展示，支持模糊搜索
[P2] 职位名称超长时动效展示
```

### 1.2 状态标记

| 标记 | 含义 | 飞书视觉样式 | 使用场景 |
|------|------|-------------|---------|
| `[TBD]` | 待定，需跟人确认 | 🟡 黄色高亮背景 `rgba(255,246,122,0.8)` | 附 @负责人 + 预计时间 |
| `[OPEN]` | 待讨论，没有结论 | 🟣 紫色高亮背景 `rgba(205,178,250,0.7)` | 需要会议/决策 |
| `[BLOCKED]` | 被卡住，等外部 | 🔴 红色高亮背景 `rgba(255,183,183,0.7)` | 附等谁、等什么 |
| `[DEP]` | 依赖项 | ⚪ 灰色高亮背景 `rgba(222,224,227,0.7)` | 附依赖谁、当前状态 |
| `[RISK]` | 风险点 | 🟠 橙色高亮背景 `rgba(255,220,158,0.7)` | 附影响范围 |

**用法：** @负责人紧跟标记，用空格隔开。
```
[TBD] @技术侧 预计06/10确认  职位列表默认排序规则
[BLOCKED] @开发（金龙）  现有 Loading 机制的具体实现方式与耗时
[DEP] 企业版职位 API — 需确认接口是否就绪
[OPEN] "首次进入"判断逻辑：本地标记 vs 后端接口？
[RISK] 排期不确定，可能影响上线时间
```

### 1.3 范围标记

| 标记 | 含义 | 使用场景 |
|------|------|---------|
| `[IN]` | 本期范围内 | 功能点、需求项 |
| `[OUT]` | 本期不做，明确排除 | 功能点、需求项（附后续版本计划） |

```
[IN] [P0] 单选职位
[OUT] 多选职位 — 计划 V2 考虑
```

### 1.4 排版规则

1. **标记放行首**，正文跟在后面，不打断阅读
2. **@负责人紧跟标记**，用空格隔开
3. **长说明用 callout 块**，短标注用行内高亮
4. **同一段落不超过 2 个标记**，否则视觉混乱
5. **TBD 项必须附 @负责人 + 预计时间**，不能只写 TBD

### 1.5 标注说明的存放位置

**标注说明不写进 PRD 正文。** 标注规范定义在本参考文件（`prd-visual-format.md`）中，PRD 文档内直接使用标记，不在文档开头添加标注说明表。

理由：
- PRD 读者（研发、设计）通过飞书文档的标注说明表了解标记含义
- 本地 Markdown PRD 是工作文件，不需要额外说明
- 飞书上传时（Phase 7）由 AI 按本规范自动添加标注，读者通过飞书文档顶部的标注说明表理解含义

## 二、内容标记规则

| 标记类型 | 写法 | 飞书 XML 渲染 | 用途 |
|---------|------|-------------|------|
| 按钮 | 【按钮名】 | `<b>【按钮名】</b>` | 所有可点击的交互元素 |
| 高亮/强调 | 文字内容 | `<span background-color="light-orange">文字</span>` | 新增内容、关键决策、重点规则 |
| 提示/Toast | *提示文案* | `<em>提示文案</em>` + orange text | 系统反馈给用户的文案 |
| 固定文案 | 直接写正文 | `<b>` 标签包裹 | 短信、Push、弹窗等用户可见的固定文案 |
| 逻辑"且" | 条件A ∧ 条件B | `<code>∧</code>` | 多条件组合校验 |
| 必填标记 | 字段名 + ★ | `<span text-color="red">★</span>` | 必填字段标识 |
| 评审反馈-新增 | `[评审反馈-新增]` | `<b><span text-color="rgb(0,180,60)">[评审反馈-新增]</span></b>` | 评审后迭代，基于反馈新增的内容 |
| 评审反馈-修改 | `[评审反馈-修改]` | `<b><span text-color="rgb(222,120,2)">[评审反馈-修改]</span></b>` | 评审后迭代，基于反馈修改的内容 |
| 评审反馈-删除 | `[评审反馈-删除]` | `<b><span text-color="rgb(232,63,63)"><s>[评审反馈-删除]</s></span></b>` | 评审后迭代，基于反馈删除的内容（飞书中加删除线） |
| 待确认 | 【待确认：xxx】 | `<span background-color="light-yellow">【待确认：xxx】</span>` | 未确认事项，视觉醒目提醒 |
| 条件场景 | 【第一次】【第二次】【首次】【非首次】 | `<b><span text-color="blue">【第一次】</span></b>` | 显式区分不同条件下的行为，避免研发遗漏 |
| 默认值 | （默认：xxx） | `<span background-color="light-gray">（默认：xxx）</span>` | 标注默认选中、默认排序等，避免研发遗漏 |
| 权限/角色 | 【角色名】 | `<b><span text-color="purple">【角色名】</span></b>` | 显式区分不同角色看到的内容差异 |
| 边界值 | **阈值** | `<b>阈值</b>` | 标记关键阈值（如最多5个、最少2字），避免研发遗漏 |

## 三、章节级标记

| 章节 | 标记方式 | 说明 |
|------|---------|------|
| 总结流程 | `<callout background-color="light-blue" border-color="blue">` | 蓝色 callout，一眼看到全局流程 |
| 数据依赖/异常说明 | `<callout background-color="light-orange" border-color="orange">` | 橙色 callout，标记需要关注的依赖和异常 |
| 全局规则 | `<callout background-color="light-gray" border-color="gray">` | 灰色 callout，跨页面共享规则 |

## 四、表格内标记

| 场景 | 标记 | 示例 |
|------|------|------|
| 必填字段 | 字段名后加 ★ | 职位名称 ★ |
| 禁用态 | 置灰描述 | 【确认选择】（未选时置灰） |
| 边界值 | 阈值高亮 | 最多选择 **5** 个 |
| 默认值 | 括号标注 | （默认：按发布时间倒序） |

## 五、文案标记

用户可见的固定文案（短信、Push、弹窗正文、Toast等）必须完整写正文，用以下格式：

| 类型 | 写法 | 飞书渲染 |
|------|------|---------|
| Toast / 轻提示 | *Toast："文案"* | `<em>` + orange text |
| 弹窗文案 | 正文直接写，标题用<b>加粗 | `<b>` 标题 + `<p>` 正文 |
| 短信/Push | 独立行，用引用块 | `<blockquote>` 包裹 |
| 带变量的文案 | {变量名} | `<code>{变量名}</code>` |

## 六、使用原则

1. **一致性**：同一项目内所有 PRD 使用相同标记规则，不在文档开头额外说明（本规范是统一参考）
2. **目的性**：标记只为降低认知负担，不滥用。一个页面/组件说明内，高亮标记不超过 3 处
3. **不过度**：不是每个词都要标记，只标记「如果漏看会出问题」的信息
4. **与结构结合**：标记配合大表和流程图使用，不在纯文字段落里大量标注

## 七、飞书上传时的转换规则

Markdown PRD 中的标记在转为飞书 XML 时，按以下规则转换：

### 7.1 内容标记转换

| Markdown 标记 | 飞书 XML |
|-------------|----------|
| 【按钮名】 | `<b>【按钮名】</b>` |
| *Toast 文案* | `<em><span text-color="orange">Toast 文案</span></em>` |
| 【待确认：xxx】 | `<span background-color="light-yellow">【待确认：xxx】</span>` |
| **总结：** xxx | `<callout background-color="light-blue" border-color="blue"><p>总结：xxx</p></callout>` |
| **数据依赖：** xxx | `<callout background-color="light-orange" border-color="orange"><p>数据依赖：xxx</p></callout>` |
| **全局规则：** xxx | `<callout background-color="light-gray" border-color="gray"><p>全局规则：xxx</p></callout>` |
| `字段名` | 正常文字（产品文档不用 code 标记字段名） |
| 【第一次】【第二次】 | `<b><span text-color="blue">【第一次】</span></b>` |
| `[评审反馈-新增]` | `<b><span text-color="rgb(0,180,60)">[评审反馈-新增]</span></b>` |
| `[评审反馈-修改]` | `<b><span text-color="rgb(222,120,2)">[评审反馈-修改]</span></b>` |
| `[评审反馈-删除]` | `<b><span text-color="rgb(232,63,63)"><s>[评审反馈-删除]</s></span></b>` |
| 【首次】【非首次】 | `<b><span text-color="blue">【首次】</span></b>` |
| （默认：xxx） | `<span background-color="light-gray">（默认：xxx）</span>` |
| 【角色名】 | `<b><span text-color="purple">【角色名】</span></b>` |

### 7.2 标注规范转换

| Markdown 标记 | 飞书 XML |
|-------------|----------|
| `[P0]` | `<b><span text-color="rgb(232,63,63)">[P0]</span></b>` |
| `[P1]` | `<span text-color="rgb(222,120,2)">[P1]</span>` |
| `[P2]` | `<span text-color="rgb(51,112,255)">[P2]</span>` |
| `[TBD]` | `<span background-color="rgba(255,246,122,0.8)">[TBD]</span>` |
| `[OPEN]` | `<span background-color="rgba(205,178,250,0.7)">[OPEN]</span>` |
| `[BLOCKED]` | `<span background-color="rgba(255,183,183,0.7)">[BLOCKED]</span>` |
| `[DEP]` | `<span background-color="rgba(222,224,227,0.7)">[DEP]</span>` |
| `[RISK]` | `<span background-color="rgba(255,220,158,0.7)">[RISK]</span>` |
| `[IN]` | `<span text-color="rgb(51,112,255)">[IN]</span>` |
| `[OUT]` | `<span text-color="rgb(140,140,140)">[OUT]</span>` |
