# Phase 0：信息提取与项目记忆

## 输入

- 会议录音转写、会议纪要、访谈记录、历史 PRD、MT 反馈、现有 PRD。
- `项目上下文.md`、`内部术语表.md`、`项目工作记录.md`。

## 动作

1. 提取项目背景、目标、范围、变更模块、约束、干系人、待确认事项。
2. 对比历史 PRD 与新材料，标注新增、修改、删除、冲突。
3. 用“新来的实习生只看资料能否理解”判断内部术语；更新 `内部术语表.md`。
4. 判断需求规模和交付深度。
5. 将过程写入 `项目工作记录.md` 或需求点 `10-过程记录.md`。

## 深度判定

| 深度 | 适用场景 | 必写内容 |
|------|----------|----------|
| 轻量 | 单页、文案、字段、简单规则 | 简要背景、核心流程、字段/交互、关键异常 |
| 标准 | 常规功能、1-2 个模块 | 正常/异常流程、字段、交互、文案、关键约束 |
| 完整 | 0 到 1、跨部门、权限/支付/合规/核心指标 | 完整流程、关键非功能约束、外部依赖、风险降级、图表 |

暂停点：必须通过结构化确认来确认项目层级、范围、交付深度、关键假设；未确认内容只写候选判断和 `【待确认：...】`。
