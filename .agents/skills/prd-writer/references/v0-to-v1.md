# V0.1 → V1.0 方法论：从"不可开发"到"能商量"

## 核心升级：三项能力

### 1. 条件-动作-预期的认知
每句话按以下语序书写，这是需求描述的基本语法：

```
当【什么条件】→ 做【什么动作】→ 预期【什么结果】
```

**页面/组件说明必须使用表格**，不要用 bullet list 逐条罗列：

| 页面/组件 | 原型图 | 维度 | 详细说明 |
|---------|--------|------|---------|

每个页面下按需填写维度行：**触发条件**/**核心流程**/**异常**/**系统逻辑**/**信息架构**/**字段**/**交互**/**文案**/**边界**/**权限**，一目了然。

**为什么重要：**
- 条件说不清楚 → 功能边界模糊
- 动作说不清楚 → 研发不知道实现什么
- 预期说不清楚 → 测试无法写用例，验收无标准

**示例：**
- ✅ 当手机号格式正确且未注册过 → 系统触发短信发送 → 预期用户收到验证码
- ❌ 发送验证码（缺少条件和预期）

### 2. 格式意识
使用 Markdown 结构化书写，培养层级思维：

| 符号 | 含义 | 用途 |
|------|------|------|
| `# ## ###` | 标题层级 | 章节结构 |
| `- ` | 无序列表 | 并列关系 |
| `1. 2. 3.` | 有序列表 | 顺序关系 |

**页面/组件说明格式：**

按页面/组件组织，使用表格（列：页面/组件 | 原型图 | 维度 | 详细说明），每个页面下按需填写维度行：
- 触发条件、核心流程、异常、系统逻辑、信息架构、字段、交互、文案、边界/异常、权限/角色

**为什么重要：**
- 让阅读者（研发/测试）条理清晰
- 让书写者自己理清逻辑
- 层级结构 = 逻辑关系（母子集 / 并列 / 顺序）

### 3. 流程意识
画标准流程图，覆盖正常+异常：

| 图形 | 含义 |
|------|------|
| 半圆（开始/结束） | 流程起点和终点 |
| 方框 | 动作（写清楚谁做的） |
| 菱形 | 判断（有 Yes 就必须有 No） |

**核心原则：流程自洽**
- 有 Yes 分支就必须有 No 分支
- No 分支的处理方式必须明确
- 异常流程引导用户修正后回到主流程

**推荐：** 多角色场景使用甬道图（泳道图）

## V1.0 自检标准
- [ ] 每句话都符合 条件→动作→预期 结构
- [ ] 页面/组件说明使用表格格式（页面/组件 | 原型图 | 维度 | 详细说明）
- [ ] 文档有 Markdown 格式，目录层级清晰
- [ ] 有完整流程图（含异常分支）
- [ ] 流程自洽（每个判断节点都有 Yes/No）
- [ ] 明确了应用端兼容性（PC/H5/App）
